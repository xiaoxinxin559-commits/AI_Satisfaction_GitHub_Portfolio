# 方法边界与可复核性

## 公开实现与原分析的关系

公开仓库是一套新的合成数据方法演示。原数据、原 SQL、原 Python、SEM 规格、原报告与估计结果文件没有提供，因此无法独立核对历史系数，也没有声称完成原项目数值复现。

本次实现的范围为数据质量检查、事件聚合、标签泄漏诊断、分组留出、OLS / 有序 Logit 演示与可视化。以下方法取舍不应被误写成历史项目已经验证的结果。

## 必须分清的六件事

**1. 二元结果不是不能进入 SEM。** 二元与有序内生变量需要与其尺度匹配的估计方案；例如 lavaan 的 `ordered=` 路线可使用 WLSMV。将评分近似连续是一项假设，而不是唯一正确选择。把评分二值化会改变问题并损失等级信息。不能把“连续 SEM 与二元建模完全不兼容”当成方法论结论。[1]

**2. 门控标签换个位置并不会自动变成独立测量。** 当问卷按评分展示标签时，标签携带了评分规则。作为前因会产生信息泄漏；改成满意度的测量指标或合成净分，也仍需审查问卷门控造成的依赖、模型识别、独立效度与约束。仅凭 CR、AVE 和拟合指标不足以消除这一问题。公开演示因此只把标签用于反馈描述和错误模型反例。[1][2]

**3. 条件系数不同于零阶相关，也不同于干预效果。** 控制其他变量后，系数表达的是条件关联。符号变化可能来自变量定义、相关结构、遗漏因素或选择机制。分层结果可以提供排查线索，但不会单独证明“某行为导致用户不满”。[3][4]

**4. R² 不能脱离同一目标与同一评估方式横比。** 评分回归的 R²、潜变量的解释比例、二元模型的 pseudo-R² 不能直接相减当成预测提升。加变量后样本内 R² 上升本身不证明模型更可用。共线性主要影响系数稳定性和解释，不意味着算出的 R² 在数值上一定错误。条件数还受量纲影响，应结合标准化设计矩阵、VIF 与敏感性检查。[3]

**5. 留出集不能挽救结果之后的标签泄漏。** 将评分后标签同时放进训练和测试，可能在留出集上也得到很高分，却不符合实际预测时的信息可用性。预处理统计量只在训练集拟合，参与者不跨训练/留出集，是公开演示新增的工程检查；不据此宣称原分析已经完成这些验证。[2]

**6. 有序模型不是无条件的标准答案。** 公开演示的 Ordered Logit 保留分数等级，但仍有比例优势等假设。模型收敛不等于这些假设已经满足。OLS 使用近似等距分数并报告参与者聚类区间；有序模型仅报告方向对照，不将系数幅度与 OLS 直接比较。[5]

## 本次数据与模型约定

分析单元是会话问卷。人工生成重复记录、无效评分、匿名标识、常量列和跨版本缺失列，用于检查流程能否拦截这些问题。合成 ID 不对应真实个人。

事件聚合仅计入问卷前 24 小时内、且属于同一会话的事件。无匹配事件被计为零建立在**演示事件日志完整**的假设上；真实业务需要先检查埋点覆盖，不能将缺失等同于未发生。

模型预先使用四个行为演示字段与三个控制项，不通过反复挑选显著结果优化叙事。P99 缩尾、log1p 与标准化在训练集拟合。年龄组采用有序近似并设置缺失标记，仅作演示，不作为所有缺失机制的通用处理方案。

独立评测交叉表分别定义用户高分 `score >= 4` 与评测高分 `expert_score >= 2`；这两个阈值是演示规则，不是经过校准的统一量表，不用于声称“评测一致性”或“产品安全合格率”。
