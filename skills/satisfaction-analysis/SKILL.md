# 满意度分析协作 Skill

本文件依据工作记录中的方法重新编写，不是原企业 Skill，不包含专有工具接口，也不代表已经安装到任何 Agent 平台。应按目标平台格式进行适配和测试。

## 先确认

一次性问清分析目标、样本单元、评分尺度、事件窗口、问卷跳转规则、可交付范围与数据权限。分清解释关联、预测和因果评估。字段不明确先问，不自行改名或猜测。

## 执行阶段

1. 逐字段盘点：所有字段都要有角色、覆盖率、变异情况和去向，包括 ID、类别、多值字段与空列。
2. 数据质量：核对去重主键、匿名标识、无效评分、埋点断裂、缺失机制与异常值；不为提高拟合度随意删样本。
3. 时序检查：区分事前特征、同期反馈、评分后标签与下游结果。评分门控标签不得直接进入预测前因。
4. 模型方案：依据连续近似、二元、有序或计数结果选择模型。使用潜变量时先审查识别与测量假设，不能只追拟合指标。
5. 诊断：异常系数先查口径、样本、相关结构、共线性与约束；必须确认对比模型真的修改了目标参数。
6. 解释：分别报告零阶关联、条件关联、预测性能及仍待验证的机制。不同量纲的系数与 R² 不直接比较。
7. 交付：代码、参数、结果表、图表底数、结论、建议、局限与版本说明一并保存。外部公开前再次确认权限。

## 人工决策关卡

指标口径、因果方向、模型路线、反直觉结果的解释、产品建议优先级与公开发布须由人确认。Agent 不能自行把假设升级成事实，不能补造数值、引用或已完成的业务收益。

## 输出格式

每个大步骤回答：做什么 → 为什么 → 如何做 → 得到了什么 → 能说明什么、不能说明什么 → 下一步。

每条正式数字注明样本版本、模型版本、估计口径和来源表格。方法图与结果图区分；示意内容写“示意”，合成数据写“合成”。

## 退出与降级

发现不可用字段、门控泄漏、不可识别模型或未收敛结果时，不强行给结论。保留诊断并提出可解释的简化方案。测量证据不足时可以改用显变量分析，但不能把这种回退说成已证明原构念不存在。

## 记忆与复盘

只保存经用户确认的非敏感协作偏好、版本决策与方法教训。禁止在公开记忆中保存原始健康对话、个人标识、公司链接或凭证。推测的工作风格需标注推测，不作人格或心理诊断。
